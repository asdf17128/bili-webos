# 设计调研:什么设计适合这个 app

**问题**:BiliTV 想做一次全面的外观优化。抄谁?抄到什么程度?哪些平台惯例对我们**不成立**?

**方法**:① 把现有 7 个页面在 1920×1080 下逐屏抓图,② 复查 tvOS / webOS / Fire TV
的 10-foot 手册,③ 看 2025–2026 三次大改版(Netflix TV、Apple TV/tvOS 26、云视听小电视),
④ **用真实数据渲染两版高保真稿**,而不是拿色块示意图讨论。

**结论先行**:走**方案 A「安静的画廊」** —— 界面本身尽可能不发声,把所有对比度和色彩预算
留给封面。**方案 B(大图沉浸式)已被自己的稿子证伪**,理由见 §三,这条是本次调研最硬的产出。

---

## 一、现状诊断(基于抓图,不是印象)

| 页面 | 问题 | 严重度 |
|---|---|---|
| 搜索 | **右半屏完全空白**;热搜是一列纯文本 + 🔥 emoji,没有层级;整页信息量约等于一个手机列表 | 高 |
| 直播 | 只有 3 张卡,下面 2/3 屏空着;没有「直播中」角标,没有人气数强调 | 高 |
| 首页 | 一整片无限网格,没有任何分组;**没有「继续观看」** —— 电视上最高频的意图反而没入口 | 高 |
| 全局 | 侧栏 14 个 **emoji 图标**:彩色、风格不统一(🏠🔥📡👤⭐🎮📺🎵📚🎭😜),3 米外糊成一团 | 中 |
| 全局 | 焦点环 `#00a1d6` 青色 + 深蓝底 `#0a0d1a`,整体读作"科技/工具",不是娱乐 | 中 |
| 首页 | 标题 1 行 / 2 行不定,卡片高度参差,行底边缘呈锯齿 | 中 |
| 品牌 | 左上角是 "B站 / webOS" 两行小字,不是一个记得住的标识 | 低 |

## 二、三个参考对象,各自只能抄一半

| 对象 | 值得抄 | 不能抄的理由 |
|---|---|---|
| **Netflix 2025 改版** | 焦点态直接把上下文摊开(类型/简介/时长);卡片上打标签("本周第 1""新一季") | 它把左侧栏改成了**顶部横向导航**。我们侧栏有 14 项(含 6 个分区),横向放不下;而且遥控器左键回侧栏是本 app 已经稳定的肌肉记忆 |
| **Apple tvOS 26** | Liquid Glass 的思路:**层次靠明度和模糊,不靠描边**;一屏放更多内容 | 它的前提是**竖版海报艺术**。我们没有海报,只有 16:9 的 UGC 缩略图 |
| **云视听小电视** | 中文用户对"顶部分类 + 精选优先"的熟悉度 | 它是 PGC 产品(番剧/影视/纪录片),内容有统一的美术规范。我们是 UGC,封面由几十万个 UP 主各画各的 |

## 三、最关键的一条:UGC 缩略图 ≠ 海报艺术

这是本次调研唯一一条**靠做稿子才发现、光看手册发现不了**的结论。

Netflix / Apple 的大图沉浸式布局(焦点项占据半屏做背景)之所以成立,是因为片方
提供了**为大画幅设计的、留白克制的海报**。B站的封面正相反:

- 封面上**自带巨大的中文标题文字**(见任意一屏抓图,几乎每张封面都有 30–60px 的粗体大字)
- 高饱和描边、箭头、红圈、表情包 —— 缩略图本身就是在小尺寸下抢注意力的产物
- 标题是长句钩子(「最强一周突击0.5折!!!《博德之门3》时隔一年终新低!Steam本周20款…」)

把这种素材放大到 1200px 宽做背景,结果就是 `mock_B_home.png`:**封面上的字比我们自己的
标题还大,两套文字互相打架**,标题被迫换到 4 行。这不是执行问题,是素材属性决定的。

由此推出本 app 的**第一设计原则**:

> **界面必须安静。** 封面已经在尖叫了,任何额外的颜色、发光、渐变、装饰,都是在和内容抢
> 同一份注意力预算。chrome 的目标不是"好看",是"让人注意不到它"。

这条同时解释了为什么当前的青色焦点环别扭:`#00a1d6` 是高饱和色,和封面里的高饱和文字
处在同一个亮度/彩度区间,焦点因此**不够跳**。白色环反而更醒目 —— 因为它是唯一不参与
竞争的"非颜色"。tvOS 用白色环不是审美偏好,是这个道理。

## 四、方案 A「安静的画廊」:设计系统

### 4.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#141518` | 中性暖灰底(现状 `#0a0d1a` 偏蓝,拉冷了整体) |
| `--rail` | `#1a1b1f` | 侧栏 |
| `--card` | `#1e1f24` | 卡片底 |
| `--line` | `#2a2b31` | 分隔线(1px,极弱) |
| `--fg / fg2 / fg3` | `#f2f2f4` / `#a1a4ad` / `#7e828c` | 主/次/弱文字 |
| `--pink` | `#fb7299` | **只用于:选中态、进度、直播角标、品牌字**。禁止用于大面积背景 |
| `--focus` | `#ffffff` | 焦点环唯一颜色 |

蓝色 `#00a1d6` 退役为链接色。**全局彩色预算:粉色出现次数每屏 ≤ 3 处。**

### 4.2 焦点态(整套设计里最重要的元素)

```
白色 4px 环 + scale(1.04) + 0 22px 44px rgba(0,0,0,.6) 阴影
```

三层同时作用:环负责"是哪个",缩放负责"跳出来",阴影负责"浮起来"。
只用 transform / opacity 动画,150ms。列表行不缩放(tvOS 惯例),用背景+描边。

### 4.3 图标:emoji → 单色线性

24px 网格、1.8px 描边、`currentColor`。理由不是审美:
- emoji 在不同 webOS 版本上字形不一致(同一个 📡 在 webOS 5/6 上是两个样子)
- 彩色 emoji 参与色彩竞争,违反第一原则
- 3 米外识别靠**轮廓**,线性图标的轮廓比 emoji 干净

已画好 14 个(搜索/推荐/热门/直播/关注/收藏/稍后再看/游戏/动画/音乐/知识/娱乐/我的/设置)。

### 4.4 版式

沿用 `DESIGN.md` 的字号阶梯,补两条:
- **卡片文字块定高 112px**(标题 2 行截断 + 副行),消除行底锯齿
- 标题 22px / 副行 18px / 时长角标 17px —— 均 ≥16px 下限

### 4.5 结构:首页加「继续观看」

电视上最高频的意图是"接着看",现在却要去「我的」里翻。首页第一行改成
**继续观看**(带进度条),下面才是「为你推荐」网格。这一条的价值可能超过所有视觉改动 ——
它直接影响我们测出来的 1.1 天/周的打开频率。

### 4.6 搜索页重做

现在右半屏是空的。改成两栏:左「热搜榜」带序号(前三名粉色),右「最近搜索」胶囊 +
「猜你想看」2×2 网格。空屏被填满,且填的是**能直接按下去的东西**,不是装饰。

## 五、明确不做

| 不做 | 理由 |
|---|---|
| 大图 Hero / 沉浸式背景 | §三,已被自己的稿子证伪 |
| 顶部横向导航(Netflix 2025 式) | 14 项放不下;且会打断"左键回侧栏"的既有肌肉记忆 |
| 毛玻璃 / 背景模糊(Liquid Glass) | Chromium 68 上 `backdrop-filter` 要么不支持要么走软件合成,TV 上必掉帧 |
| 卡片悬停自动播放预览 | 老电视解码资源紧张,且会和弹幕/播放器抢管线 |
| 圆角再加大 / 更多描边发光 | 违反第一原则 |

## 六、落地分期

| 期 | 内容 | 风险 |
|---|---|---|
| **1** | 色彩 token + 白色焦点环 + 14 个线性图标 + 卡片定高 | 全局 CSS,风险集中但可控;逐屏截图对比 |
| **2** | 首页「继续观看」行 + 搜索页两栏重做 | 涉及焦点行列模型,需重跑滚动几何断言 |
| **3** | 直播页(直播中角标/人气)、空状态、加载态、播放器控制栏图标化 | 面广但都是局部 |

每期出浏览器截图给 owner 过目再进下一期;每期跑 `verify.sh --no-tv --sim` 全绿才算完。
