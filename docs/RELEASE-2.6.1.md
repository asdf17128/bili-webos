# 2.6.1 发布验证

日期：2026-11-15（Asia/Shanghai）。公开功能说明见 [2.6.1 更新说明](releases/v2.6.1.md)。

## 范围

本版整合 legacyfix.1–7：旧机型设备激活兼容修复、播放控制栏更新隔离、长按快进预览和跳转延后、10 秒步进与明显选中状态、弹幕独立紧凑行距，以及有界控制响应诊断。

#34 报告者确认此前登录播放恢复、进度条意外跳跃改善，但 legacyfix.7 对播放中的间歇卡顿没有明显进一步改善。此问题仍开放；不能将本地浏览器性能测量或新电视表现外推为 Chromium 53 设备已修复。

#69 是 #29 同一报告者在香港 HKBN、自动择优、指定视频 1080p 下的成功反馈，两条已回复并关闭。其他网络、账号和设备问题没有据此一并关闭。当前无待合并 PR。

## 验证流程

- 执行 `bash tools/verify.sh --no-tv --ux`。
- 首轮在播放加载套件出现四项弹幕字号超时：模拟解码器缺少正常加载的 `loadedmetadata` 事件，导致按媒体事件采样的时钟未获得夹具设置的播放时间。修正测试夹具的事件序列，保留专测中故意延迟的元数据事件；应用代码未为此改变。
- 四档字号专项修正后 4/4 通过，随后重新启动整套管线。首轮日志保留于 `/tmp/bili-261-verify-first.log`，第二轮日志为 `/tmp/bili-261-verify-final.log`。
- 首轮 Docker 未启动，已启动后单独验证真实 Node 0.12.2／8.17.0，通过；最终管线再次执行该门禁。

- 第二轮完成到直播套件，发现旧断言仍要求 8 个设置项；新增行间距后正确数量为 9。更新断言并增加直播间距保存、密度保持及不重连验证，完整直播套件重跑 16/16 通过。随后顺序补跑播放健康、CDN、诊断与本地网络探针；日志 `/tmp/bili-261-verify-tail.log`。没有把中途停止的整套管线写成单次退出码 0。
