# 分段弹幕验证（未发布测试分支）

## 范围与方法

优先解决旧 XML 弹幕池对视频后段覆盖不足的问题。本轮是独立实现 protobuf 分段读取，不移植 Android 渲染器，不查询历史弹幕。研究依据见 [功能文档](../../FEATURES.md)。

- 当前六分钟分段优先，预取下一段，最多缓存三段；请求失败有冷却，XML 仅作降级。
- 单响应最大 4 MiB；最多解析 50,000 条，超过 20,000 条时按整段时间均匀抽样。渲染同时显示数量仍受用户密度设置约束。
- 拖动后忽略不再相关的响应；退出后不发布迟到结果。分段更新保留正在屏幕上的动画。

## 本地验证

`tools/test-danmaku-segments.mjs` 覆盖 protobuf Unicode/大 ID、损坏响应、大小保护、超过 2 MiB 的合法响应、整段均匀抽样、跨段去重、跳转、失败降级、冷却、关闭以及模拟 80 分钟时间线。模拟时间线只验证算法，不等于真机长测。

`tools/test-player-loading.mjs` 通过模拟 Luna 返回 base64 二进制响应验证真实播放器集成。`tools/test-danmaku-render.mjs` 验证分段替换不会清空正在显示的弹幕节点。

全量入口：`bash tools/verify.sh --no-tv --ux`，最终运行通过。包含真实 Node 0.12.2 / Node 8 服务兼容检查、生产构建、74/74 遥控 UX、62/62 推荐菜单、26/26 账号修复 UI、84/84 播放加载、38/38 控制栏、7/7 分段弹幕、15/15 直播加载，以及弹幕渲染、字幕、诊断、CDN 与退出恢复等回归。完整原始日志保存于 `/tmp/bili-dm-full-verify-final.log`。

本地首次全量运行的诊断报告用例暴露两项测试工具问题：模块拦截未匹配 Vite 热更新查询参数；jsQR 拒绝一个有效密集二维码。补齐模块匹配，并以 ZXing 从相同截图像素独立识别；没有绕过报告内容和隐私断言。该二维码也经 macOS Vision 独立解码确认。

## 真机验证

工具：`tools/test-danmaku-soak-tv.mjs`。使用真实时钟，默认 80 分钟，每 30 秒记录数值状态，每五分钟测试登录 API 连通。记录不包含 cookie、签名播放地址或账号信息。结束时恢复原始设置并退出播放器。

阶段：前 40 分钟高密度弹幕片源，20 分钟时退出再进入并提高密度与字号；后 40 分钟 4K 片源，最后 20 分钟额外执行定向跳转。检查解码进度、长停顿、页内异常、API 连通、弹幕请求、缓存、DOM、堆内存与退出清理。

初次短测发现登录电视返回单段约 2.6 MB、18,710 条弹幕，超过最初的 2 MiB 限制而回退 XML。将上限改为 4 MiB 后重新构建安装，独立 60 秒预检通过：正常分段请求、未降级、无播放停顿，设置恢复成功。该预检不计入正式 80 分钟。

电视 Chrome 132，测试版本 `2.5.2 danmaku-test.1`。已核对电视安装及加载的构建资源 SHA-256 与本地一致。原生视频平面不一定出现在 CDP 截图中，故结合媒体解码与时间进度；不以截图声称肉眼观看了物理屏幕。

## 首轮长测：65 分钟处中止（未通过）

计划 80 分钟；前 40 分钟完成两轮高密度片源，随后 25 分钟完成 3996×2160 播放、循环与首次跳转。第 65 分钟第二次定向跳转后，脚本固定等待 4 秒即采样，读到 `readyState=1`、媒体错误为空、仍在缓冲，随即退出。这无法区分正常 seek 缓冲与卡死，因此保留为失败，不能算 80 分钟通过。

中止后设置恢复成功，空闲 DOM/监听器回到 614/212；相比开始堆内存增加 522,844 字节。此前 13 次登录 API 检查全部成功，弹幕请求没有失败或 XML 降级。4K 循环期间曾记录约 1 秒进度间隔，没有解码掉帧。

补充 `4k-seek` 专项测试配置，等待媒体完成 seek 且播放进度实际增加，最长 20 秒；每次记录目标、恢复耗时和媒体状态，超时仍判失败。额外明确断言采样时不能处于暂停。追加 20 分钟专项复测通过（真实计时 1,200,507 ms），四次跳转恢复耗时分别为 2,122 / 5,431 / 6,970 / 1,348 ms。原失败点再次出现短暂缓冲，但在约 5.4 秒自动恢复，证实固定等待 4 秒的判定不适合此路径。不能据此把原始失败运行改写成通过。

两轮累计约 85 分钟，合计 18 次登录 API 检查全部通过；弹幕请求没有失败或降级，缓存最多三段，屏上弹幕最多 48 条。采样中未出现媒体错误或解码掉帧，4K 实际分辨率为 3996×2160。专项结束后的空闲堆内存较本轮开始增加 143,388 字节，DOM/监听器回到 614/212；设置逐字恢复成功，播放器已退出。

**限制：连续 80 分钟验收仍未通过；本轮证据是 65 分钟中止 + 20 分钟专项通过。4K 跳转存在约 1.35–7 秒等待，尚未优化该耗时。没有取得用户对本次物理屏幕的额外目视确认，真机结论基于设备 CDP、媒体解码、截图和网络/资源采样。未发布正式版。**
