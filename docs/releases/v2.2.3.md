# v2.2.3 — 播放器布局与起播诊断

根据 [#34 的新反馈](https://github.com/asdf17128/bili-webos/issues/34#issuecomment-6014078076)，修复推荐面板挤压控制栏的问题，并补充旧电视起播排查信息。

- 推荐列表展开后，进度条不再被压到 0 像素；标题、元信息、进度条、按钮和推荐标签按正常内容高度排列。间距不依赖旧 Chromium 缺失的 flex gap。
- 从推荐列表返回控制按钮时自动将焦点滚回可见区域，大字号换行也能操作。
- **设置 → 网络诊断** 直接显示最近一次起播耗时。播放器初始化、媒体连接、视频信息、续播查询、取流、杜比探测及媒体加载分别计时；并行阶段不能相加。
- 扫码报告增加从打开视频到媒体请求/响应、元数据、媒体就绪及播放事件的时间，保留重试、失败/退出状态和编码。仅在内存保存固定字段，不记录签名媒体地址或认证信息。

总起播时间仍以 `loadeddata` 为准，不是逐帧画面测量。C9 报告者在 v2.2.2 仍测得 16–18 秒，本版用于区分接口、媒体下载及就绪等待；**尚未定位 C9 根因，也不承诺本版缩短这 17 秒**。#34 保持开放，更新后播放同一视频，再返回设置打开诊断即可提供新的阶段数据。

## 验证

本地遥控 **61/61**、加载 **28/28**、片尾 **26/26**；弹幕、直播与 CDN 回归通过。真实网络模拟 **54 通过 / 0 失败 / 3 跳过**。C4 全量 **54 通过 / 0 失败 / 2 跳过**，遥控与控制栏 **31/31**、片尾 **13/13**、CDN/诊断二维码 **13/13**。跳过项为未登录的模拟账号功能、真机单档直播切换及账号列表写操作。

验证结果与设备边界见 [TESTCASES.md](https://github.com/asdf17128/bili-webos/blob/v2.2.3/docs/TESTCASES.md)。可用真机为 LG C4；旧 CSS 降级测试和真实 Node 0.12.2 服务测试不等于 C9 整机验证。

## English

Fixes progress-bar compression when the recommendation shelf expands, removes its reliance on flex gap, and scrolls focused controls back into view. Diagnostics show the most recent startup duration on screen and include stage timings, media milestones, retries and codecs in the QR report. Failed or cancelled startup retains partial evidence.

The reported C9 delay remains under investigation. This release adds diagnostic evidence; it does not claim a confirmed startup speed improvement on that device.
