# 人物遮罩连续播放闪烁排查（2026-11-07）

旧实现已在电视上记录到遮罩反复消失。本轮改为稳定的内联 SVG 遮罩引用，并补上原生视频帧回调静默时的 rAF watchdog。**最终包的本地回归与 30 秒电视自动化复验通过：446 个电视样本中没有遮罩丢失、开关切换或过期轮廓。** 首轮中间失败保留在下文。实体屏幕上的遮脸效果和流畅观感尚未获得用户确认，当前未发布。

## 电视故障基线

[脱敏电视记录](tv-before.json)保留相对时间、播放位置、遮罩状态和准备耗时，删除原始环境信息；没有视频标识、网络地址、签名 URL 或凭据。

- 采样窗口 13,949 ms，共 208 个样本，播放持续进行，全部 `readyState=4`。
- 91 个样本处于 `waiting`，同样 91 个样本没有应用遮罩，占 43.75%。相邻样本共记录到 41 次遮罩有／无切换；这不是逐个显示帧的完整统计。
- 采样中的最近一次 `prepareMs` 中位数为 59 ms，最大 203 ms、最小 28 ms。该分布是状态采样值，不是独立解码任务的耗时分布。
- 另外三次分阶段测量的完整准备耗时分别为 **69.5 / 38.9 / 39.7 ms**，涵盖 SVG 解析、源图解码、像素读取、边缘处理、PNG 编码及输出图解码。

旧实现同时只准备一张图片。连续变化的轮廓在 25 fps 下约每 40 ms 更换一次；准备工作落后后，80 ms 旧轮廓期限会清除遮罩，后续结果赶上时又重新应用。不能通过无限延长旧轮廓寿命掩盖这种吞吐不足，否则人物移动和切镜时会保留错误形状。

## 旧实现在本地复现

[旧实现连续播放基线](continuity-baseline.json)使用本地保存的公开真实 `.webmask`，连续播放时间窗口为 1–6 秒。检查的 1–6.5 秒源窗口包含 138 帧、102 个不同 URI，避免少量重复轮廓全部命中缓存。

| 准备延迟 | rAF 样本 | 无遮罩样本 | 有／无切换 | 轮廓更新 |
|---|---:|---:|---:|---:|
| 未注入 | 301 | 0 | 0 | 91 |
| 准备函数前等待 100 ms | 301 | 202（67.1%） | 3 | 6 |

两种场景都没有保留超过 80 ms 的旧轮廓，但慢准备场景长期没有可用遮罩。原来的重复 URI 测试主要检查背景仍可见，没有覆盖持续产生新轮廓时的人物保护连续性。

## 新实现与本地回归

渲染层保持同一个内联 SVG `mask` 引用，只更新已校验的几何形状，不再等待每帧图片解码。仍保留 80 ms 期限、跳转时立即清除、切源隔离和失败退出。当前段与下一段最多缓存两段，已准备几何最多缓存 8 帧。

边缘留白仅用于能够确认的单个闭合填充几何；其它形状保留源轮廓，不套用近似外扩。遮罩按视频实际比例定位，黑边区域继续显示普通弹幕；不读取视频画面或在电视上运行人像识别。

[连续播放测试](../../../tools/test-danmaku-mask-continuity.mjs)默认生成 400 个不同的人形轮廓，不依赖外部网络或 `/tmp` 媒体文件。本次每个场景连续运行 8 秒，窗口包含 206 个不同 URI，使用逐帧 rAF 采样，并抽取中央人物洞与左右背景像素。结果见 [continuity-vector.json](continuity-vector.json)。

| PNG 解码延迟设置 | rAF 样本 | 无遮罩／切换／过期轮廓 | 轮廓更新 | 图片解码调用 | 像素抽检 |
|---|---:|---|---:|---:|---|
| 0 ms | 480 | 0 / 0 / 0 | 200 | 0 | 4/4 通过 |
| 100 ms | 481 | 0 / 0 / 0 | 200 | 0 | 4/4 通过 |

新实现不调用 PNG 图片解码，因此第二行的延迟没有进入实际渲染路径。这验证了连续渲染不再依赖该异步阶段，并不代表 SVG 几何计算在任意慢设备上都没有成本。

**两组本地实验不是严格 A/B。** 旧基线使用真实源，并在整个准备函数前等待 100 ms；新回归使用可生成的人形源，仅延迟实际 `Image.decode()` 的 PNG 分支。片源、持续时间和延迟注入位置均不同，不能把 67.1% 与 0% 解读为同条件下的性能提升比例。

复现方式（先启动本地 Vite）：

```sh
node tools/test-danmaku-mask-continuity.mjs
```

可用 `MASK_CONTINUITY_REAL_FILE` 指定本地真实 `.webmask`、`MASK_CONTINUITY_START` 和 `MASK_CONTINUITY_SECONDS` 选择连续窗口。真实源模式不套用合成轮廓的固定中心像素预期，截图需按实际源轮廓检查。默认输出在 `/tmp/bili-mask-continuity/`；本目录只保存脱敏 JSON，截图文件名对应测试运行时产物。

## 真实影片与真实遮罩的本地补充

[真实影片验证摘要](real-media-vector.json)记录两份本地媒体的实测结果，仍不属于电视验证。

- Rick 样本连续播放测试运行 120 秒，取得 120 个进度样本，相邻样本的 119 个间隔全部推进；没有媒体错误或遮罩失败，源分段缓存不超过 2、几何缓存不超过 8。
- 4.95 秒画面选择了 `x=780, y=430, width=220, height=460` 的头脸区域，对比有弹幕与原画面，差异阈值 40 时为 **0 / 101,200 像素变化**；同时人工查看截图，头脸区域干净。这个结果只证明该帧的所选区域，没有推广为整段视频的人脸准确率。
- 7.75 秒仍有人物，但官方源帧没有人物洞；程序显示无保护状态并保留普通弹幕。这是源数据覆盖边界，不能算作“已避开人物”。
- 第二样本在 17.9 秒采用 `current-transition` 保留当前轮廓，18.02 秒切换到源帧无洞状态。17.9 秒画面中的贴纸本来就不在源保护范围内，不把它作为人脸准确性的证明。

另使用真实 `.webmask` 运行连续时钟回归，结果见 [continuity-vector-real.json](continuity-vector-real.json)。0 / 100 ms PNG 延迟设置下，各有 301 个样本、91 次轮廓更新，均为 0 次无遮罩、0 次有／无切换、0 次过期轮廓。**真实源模式没有断言固定中心像素**，其中截图的 `pass` 为 `null`；报告中通用检查项的 `centralHoleAndBackground=true` 不代表真实人物像素全部通过。

## 首轮矢量版电视验证：保留中间失败

[首轮矢量版电视记录](tv-vector-intermediate.json)来自 `2.5.2 danmaku-mask.2`，保留原报告的 `pass=false` 与断言错误，不将其改写为最终通过。

- 30 秒、592 个样本，无遮罩 0 次、有／无切换 0 次、遮罩失败 0 次，播放推进 29.96 秒；几何准备耗时的采样中位数为 4 ms、最大 15 ms。
- 原脚本要求轮廓更新次数 `>300`，实际为 262 次，因此失败。真实源可能连续复用同一轮廓，不能把固定次数门槛作为通用性能标准，也不能用这个断言单独证明播放器丢帧。
- 独立时序复核仍找到真实问题：轮廓呈现时钟主要每 100 ms 更新，3 个样本的 `播放时间 - 源帧时间` 超过 80 ms，最大 158 ms。这与 PNG 准备已经变快是两个不同问题。
- 进一步独立探测发现，电视原生视频对象虽然提供 `requestVideoFrameCallback`，却不交付回调。旧调度据接口存在性跳过 rAF，只剩 100 ms 数据轮询驱动轮廓。

后续修复始终保持 rAF watchdog：未收到有效视频帧回调，或最后有效回调已超过 80 ms 时，由 rAF 跟随当前播放时钟；正常回调仍优先采用呈现帧时间。同代迟到且已过期的 `mediaTime` 不更新健康时间，也不允许把轮廓倒退。暂停、后台清理、跳转代际及退出双回调取消继续保留，未扩大旧轮廓期限。

浏览器回归已补充接口存在但始终静默、先正常再停滞、同代迟到回调三种情形。原有 22 项加上包含这些情形的新用例，最终为 23/23；本次矢量专项为 7/7，包含通过 `MASK_VECTOR_FILE` 启用的真实源六倍 CPU 限速可选项，默认工具为 6 项。结果见 [local-regression.json](local-regression.json)。最终 watchdog 代码下的 8 秒连续播放也已重跑，上表采用该次结果。这些是分别记录的本地套件，不相加为所谓全量通过。

同一记录还保留 121 秒、139 轮、556 次跳转的生命周期检查：源缓存最多 2 段，节点和监听器增量均为 0。**该轮压力测试发生在最终 watchdog 修改之前**，只能作为此前矢量渲染生命周期的证据；不能写成最终调度版已完成同等长测。最终构建的 7 份 legacy JS 通过 ES2016 语法解析，这也不替代实际旧 Chromium 或电视运行验证。

## 最终电视复验：自动化通过，实体观感未确认

包含 rAF watchdog 与过期回调保护的 `2.5.2 danmaku-mask.2` 已重新构建并安装到电视。[安装记录](installed-package.json)保存包 SHA256，9 个应用／服务文件的安装后 SHA256 全部匹配，并确认运行页面加载了新入口。

[最终电视记录](tv-after.json)连续运行 30 秒，播放与呈现时钟均推进 29.96 秒：

- 446 个样本，无遮罩 0 次、有／无切换 0 次、超过 80 ms 的旧轮廓 0 次；源帧最大年龄 38 ms，轮廓更新 637 次。
- 几何准备耗时的采样中位数 4 ms、最大 12 ms；缓存最多 2 个源分段、8 帧几何，没有媒体错误、遮罩失败或页面错误。
- 视频帧回调计数仍为 0，动画帧驱动计数为 1,234，确认这台电视实际通过 rAF watchdog 更新轮廓，而非依赖接口存在性。
- 检查结束后恢复原视频、约 15.34 秒的播放位置与原设置，设置逐项一致，媒体保持可播放。

**采样方法发生了变化。** 最终记录在渲染回调之后由 rAF 采样，相邻记录至少间隔 50 ms；前两轮采用 interval 采样。446、592 和 208 是各自采样数，不是屏幕帧率，也不能直接按样本数量或比例计算严格的前后提升。最终“0 次过期”限于本次记录窗口与采样方法。

已查看电视应用截图，但原生视频平面在截图中为黑层，只能检查 App 弹幕／控件叠层，不能凭这张图确认实体电视上的人物避让。实际画面观感仍待用户确认；本轮不是长期电视稳定性测试或全片源准确率验收，未发布。
