# biliwebOS 使用体验重设计 · 2026-09-06

新版作为 2.0.0 安装到开发电视 LG C4，最终发版回归见 [RELEASE-2.0.0.md](RELEASE-2.0.0.md)。下方保留各轮设计的实测记录。

## 后续调整：顶部精简与字号导航

按用户反馈移除列表页顶部刷新按钮、标语和品牌副标；推荐、热门、直播、关注、分区、收藏、我的和搜索统一压缩顶部，继续观看也移除重复说明。侧栏确认刷新保持不变。标准字号下，真机推荐页标题区由约 180px 缩至 62px，为内容增加约 118px 的垂直空间。

本次顶部调整截图：精简首页（本地截图 `ux-evidence/2026-09-06-compact/tv-home.png`）、精简搜索（本地截图 `ux-evidence/2026-09-06-compact/tv-search.png`）。本轮真机 13 项导航检查通过，记录见 [device.json](ux-evidence/2026-09-06-compact/device.json)。

设置页的字幕字号与界面字号焦点序号曾和显示顺序相反，实测向下会跳过字幕字号再折返。现按弹幕字号 → 字幕字号 → 界面字号排序。相同浏览器测试修复前 0/2、修复后 2/2，覆盖双向导航、三个选择器的确认与取消、值保存和焦点恢复。

## 后续调整：条目更紧凑

卡片文字区从 164px 收至标准四列约 111px：统一 12px 内边距，标题固定两行高度、行高 1.25，元信息占统一的 24px 行。UP 主在左、播放信息在右，标题 22–23px 与元信息 18px 字号保持不变。继续观看的标题也固定两行，进度统一对齐。网格间距由 28px 收至 24px；继续观看高度由 120px 收至 102px，搜索和设置条目也减少内边距。

用户指出第一版紧凑卡片不齐：取消标题槽位后，一行与两行标题下方的元信息相差 27.5px。现在用统一文字槽位保证基线；异步翻译增加标题长度也不会推移当前焦点卡片。

最终浏览器 39/39、真机导航 13/13 通过；真机前 12 张卡片文字区全部 111px，元信息相对文字区偏移全部 75px，三张续播进度 Y 均为 191.84375。最新截图：首页（本地截图 `ux-evidence/2026-09-06-density/tv-home.png`）、设置（本地截图 `ux-evidence/2026-09-06-density/tv-settings.png`）；记录：[浏览器](ux-evidence/2026-09-06-density/browser.json)、[真机](ux-evidence/2026-09-06-density/device.json)。

## 设计方向

采用「内容画廊」：中性炭黑底色、清晰白色焦点、线性图标、少量 B 站粉，让真实视频封面成为视觉主体。B 站 UGC 封面常包含大字和高饱和图案，因此没有把普通封面拉成巨幅背景；首页优先展示继续观看和推荐。

参考原则来自 [LG webOS：简化界面、突出内容、保持交互一致](https://webostv.developer.lge.com/develop/guides/design-principles)、[Android TV：导航抽屉](https://developer.android.com/design/ui/tv/guides/components/navigation-drawer) 与 [TV 焦点系统](https://developer.android.com/design/ui/tv/guides/styles/focus-system)。本项目采用 1.025 倍卡片放大配合 4px 白框，兼顾电视焦点辨识与高密度 UGC 布局。具体布局属于针对 biliwebOS 的设计选择。

## 已落地

| 区域 | 新体验 |
| --- | --- |
| 导航 | 112px 图标栏；移入展开文字，覆盖在内容上。主内容宽度始终固定，侧栏开合不改变卡片排版和滚动位置。14 个入口均保留 |
| 首页 | 紧凑栏目名、继续观看、推荐网格和底部遥控提示。继续观看与推荐共用滚动区域，不长期占据内容视口 |
| 视频卡片 | 标题统一两行高度，UP 主与播放信息在统一底栏对齐；文字区四列约 111px；白色完整焦点框，观看进度保留品牌色 |
| 搜索 | 原生输入框；热搜排名与最近搜索并列，两栏可以用左右键连接。输入后显示建议，确认后展示结果 |
| 收藏与个人页 | 统一页面标题、胶囊标签、用户身份区与视频卡片 |
| 设置 | 左侧说明、右侧设置；播放显示与应用账户分组。保留原有选项及原生焦点顺序 |
| 播放器 | 线性动作图标、明确的图标与文字层次；播放器按钮、画质菜单与卡片菜单使用一致焦点样式；保留原有金币图标 |

继续观看只读取已登录用户最近 30 条服务端历史，筛选最多 3 个未看完的普通视频；过滤未开始、已结束、剩余不足 15 秒、直播和不支持的历史类型。保留服务端 cid 与 progress 的对应关系，避免跳错分 P。结果按账户缓存 60 秒，退出播放后更新；读取失败不影响推荐，不展示占位的虚构内容。

用户明确的两条规则保持不变：**当前栏目按 OK 刷新并回到开头；Back / 左键到侧栏保持列表，右键恢复原卡片。**

## 实现与兼容

- `components/Icon.jsx`：本地 SVG 图标，无额外图标库、字体或图片依赖。
- `tv-design.css`：统一色彩、排版、抽屉、卡片和控件样式；由 `main.jsx` 在基础样式后导入。
- `ContinueWatching.jsx`：真实历史读取、缓存、续播卡片。
- `VideoGrid.jsx`：顶部内容与网格共用偏移；历史迟到时按实际卡片位置重新计算，深处焦点保持原屏幕位置。
- 焦点和网格滚动仍由直接 DOM 更新驱动。动画使用 transform / opacity；没有模糊玻璃、大背景轮播或自动预览。
- 保留 Chromium 68 的 16:9 padding 写法、旧版构建和图片代理；没有引入 flex gap、aspect-ratio 或 inset 依赖。

## 验证

- 浏览器 **35 个场景通过**：原有 24 个交互回归，加 11 个重设计场景。覆盖方向键、真实指针、滚轮、失败接口、迟到历史、三语大字号、两列大卡片视口、继续观看和侧栏恢复。
- LG C4 **16 个检查通过**：真实播放达到 readyState 4；深网格退出播放回同一卡片；继续观看标注 103 秒，实播 103.0 秒，退出回到续播卡片；抽屉、搜索、设置与焦点可见性正常。
- `bash tools/verify.sh --no-tv`：语法、交互逻辑、i18n、真实 Docker Node 8 服务验证及生产构建通过。最后新增的两条按钮可访问性文案另跑 i18n 检查通过；最终包重新构建并部署。
- 改前快照运行相同重设计输入场景：抽屉、继续观看、搜索横向导航 **0/3**；证明新入口和新布局确实生效。不是对原本没有的新功能声称修复。
- 开发中实际抓到并修复：大字号从设置返回侧栏，焦点按钮 bottom=982，导航可见底部=896；展开后再次校准导航滚动，回归通过。

命令：`npm run test:ux`（Vite 启动后），`npm run test:ux:tv`（已安装开发包且电视在前台）。浏览器最终记录包含完整 34 项套件及随后补充的 1 项双列大字号专项结果。
