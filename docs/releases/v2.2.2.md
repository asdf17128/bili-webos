# v2.2.2 — 减少起播等待与弹幕负担

针对 [#34 的 C9 用户反馈](https://github.com/asdf17128/bili-webos/issues/34#issuecomment-6013025918)，优化点播起播和弹幕显示：

- 播放器模块与视频信息并行加载，续播信息与取流并行请求。同一分 P 只取一次成功的续播/字幕元数据；续播到另一分 P 时，仍使用那个分 P 的视频流、章节和字幕。
- 弹幕、推荐、缩略图等辅助请求等媒体数据就绪后开始，退出后不再启动这些任务。慢弹幕接口也不会阻塞选集列表。
- 弹幕只查找当前时间附近的记录，避免每半秒重扫整段视频。密集弹幕最多同时显示 24 条，过量内容适度丢弃，保留字号、颜色与翻译。
- 暂停同步冻结弹幕；前后跳转清除旧弹幕，返回之前的位置能重新显示。
- 网络诊断新增 `startup` 数值，表示播放器打开到 `loadeddata` 的毫秒数。它不是逐帧显示测量，也不是 CDN 下载速度。

视频画质、编码选择、CDN 策略和播放结束模式保持既有行为。安装包、更新信息和 Homebrew manifest 一起发布；商店目录仍由上游同步。

验证详情记录在 [TESTCASES.md](https://github.com/asdf17128/bili-webos/blob/v2.2.2/docs/TESTCASES.md)。保留旧版正对照、受控浏览器回归及 C4 真机结果。真实 Node 0.12.2 / 8 服务测试和 Chromium 53 构建检查不等同于 C9 整机测试；C9 的起播与弹幕体验仍待报告者复测，因此 #34 保持开放。

C4 起播小样本的两组中位数分别为 1950→1824ms、1742→1845ms，网络波动下并非每组都更快；不承诺统一提速比例。可以确认的是请求串行等待减少、弹幕扫描与动画数量有界，C4 暂停/跳转行为已验证。

## English

Overlaps independent startup requests and reuses successful resume metadata without losing the selected part or saved position. Auxiliary requests wait for media readiness. Danmaku rendering uses bounded time-window lookup and at most 24 concurrent animations, freezes while paused, and clears stale text on seeks. Font sizes and translation remain supported.

Diagnostics include the time to `loadeddata`. Validation uses controlled browser tests and an LG C4; improvement on the reporting LG C9 is still awaiting community confirmation.
