# 中国区规模估计:方法与结论

**问题**:装了 Homebrew Channel 的中国 LG 电视有多少台?我们(BiliTV)覆盖了其中多大比例?

**结论先行(2026-08-02,三条路径融合)**:

| 量 | 中位数 | 80% 区间 |
|---|---|---|
| 中国区活跃 Homebrew 设备 | **约 990 台** | 615 – 1,550 |
| 我们的覆盖率 | **约 23%** | 12% – 46% |

数字由 `tools/market-mc.mjs`(蒙特卡洛)求解,每个输入的分布写在 §二。
覆盖率的分母只用路径 A、C(两者都与我们自己的装机量无关);用路径 B 当分母是循环论证
(把假设的 $p$ 原样输出),见 §三之 6。

---

## 一、为什么这题难

目标人群是典型的**隐藏人口(hidden population)**:没有注册表、没有官方统计、成员不自我披露。
社会学/流行病学里估计这类人群有成熟方法(捕获-再捕获、多重系统估计、网络规模法、基准-乘数法),
但它们几乎都需要**新采集数据**(问卷、链式招募),而我们:

- 不采集用户数据(隐私底线,也不该为了一个统计数字破例)
- 发帖做调查的样本代表性不成立(见 §五「被否决的方案」)

所以这里只用**两类不打扰任何人的数据**:公开的行业数字,和 GitHub 上可精确计数的下载量。

## 二、三条独立路径

### 路径 A:自上而下(市场漏斗)

| 环节 | 数值 | 性质 |
|---|---|---|
| 全球 webOS 设备 | 2.4 亿(2025-09,LG 官方) | 硬数据 |
| 全球 Homebrew 活跃装机 | **32,612**(hbchannel 最新版 ipk 下载) | **硬数据** |
| **全球越狱渗透率** | **0.014%** | 前两项相除 |
| 中国电视年出货 | 3,596 万台(2024) | 硬数据 |
| 外资品牌(三星+索尼+LG)中国份额 | 不足 3%(2026Q1) | 硬数据 |
| LG 中国年出货 | 10–30 万台 | **推算**(取合计的约 1/3) |
| LG 中国保有量(7 年寿命) | 70–200 万台 | **推算** |
| **× 全球渗透率** | **100–280 台** | |

### 路径 B:自下而上(从我们自己反推)

我们的活跃装机可以**精确数出来**:Homebrew 自动更新是每台设备每版下载一次,所以
"单个版本的 ipk 下载数 ≈ 当时的活跃装机数"。

| 版本 | ipk 下载 |
|---|---|
| v1.3.0 | 391 |
| v1.4.0 | 477 |
| v1.5.0 | 432 |

→ **活跃装机 ≈ 433 台**(近版均值),占全球 Homebrew 活跃装机的 **1.33%**。

设 p = "中国 Homebrew 用户里装了 BiliTV 的比例",则中国盘子 = 433 / p:

| p | 盘子 |
|---|---|
| 90% | 480 台 |
| 60% | 720 台 |
| 30% | 1,440 台 |

p 应当偏高:BiliTV 是官方目录 45 个应用里**唯一的中国向应用**,而中文用户装 Homebrew 的
首要动机就是看国产内容。

### 路径 C:按比例分配(全球硬数据 × 中国份额)

$$N_{CN} = H_G \times s \times \beta$$

$H_G$ 是硬数据(32,658),难点全在 $s$ = 中国份额,它必须由一把**与我们自身数据无关**的
钥匙来量 —— 否则又变成路径 B 的循环。用的钥匙是 **GitHub 生态参与者的地理构成**
(`tools/market-geo.mjs`,可复跑):

| 测量 | 结果 |
|---|---|
| 生态 5 仓库(hbchannel / youtube-webos / moonlight-tv / dev-manager / userscripts)的 issue 作者 | 834 人 |
| 其中资料里填了 location | 206 人(25%) |
| 判为中国大陆 | **2 人 → 原始份额 0.97%** |
| 台湾 1 · 香港 0 · 中文玩梗式 location | 0 |

原始份额 0.97% 直接乘 $H_G$ 得 **317 台**,而我们自己**数出来**的中国装机下界就有 238–390 台
(433 × c)。下界顶到上界,说明**这把钥匙系统性偏低**,必须修偏。偏差拆成两项:

| 分量 | 含义 | 取值 | 性质 |
|---|---|---|---|
| $\beta_{fill}$ | 中文用户更少填 location | 生态填写率 25% ÷ 我们 star 用户填写率 12% = **2.1** | **实测** |
| $\beta_{voice}$ | 中文用户更少在英文仓库开 issue(问题都去恩山/QQ 群/B站评论区,我们自己仓库的 issue 也是 100% 中文) | 1.0 – 3.0(对数均匀) | 先验 |

→ 路径 C:**中位 1,271 台,80% 区间 434 – 3,110**。

## 三-旧、两条路径对不上(已被 §三 推翻,保留作为记录)

路径 A 给出 100–280 台,但路径 B **实测就有 433 台**。下界超过上界,说明**模型错了**,而不是误差。

最可能的解释(按可信度排序):

1. **中国的越狱渗透率显著高于全球平均。** LG 中国版 webOS 没有 B站/爱奇艺/腾讯视频,
   不越狱几乎看不了国产内容;欧美用户官方就有 Netflix/YouTube,动机弱得多。
   若中国渗透率是全球的 3–5 倍(0.05%–0.07%),盘子 = 400–1,400 台,**与路径 B 吻合**。
2. **LG 中国保有量被低估**:水货、海淘、港版机器不进中国出货统计,而这在 LG OLED 上很常见。
3. **全球分子被低估**:不升级到最新版的老用户没被 hbchannel 最新版下载数计入。

**这个矛盾本身是有价值的产出**:两条独立路径共同指向"中国用户的越狱动机远高于全球平均"。

## 三、数学依据与近似的可靠性

### 3.0 符号

| 符号 | 含义 |
|---|---|
| $N_{CN}$ | 中国区活跃 Homebrew 设备数(**待估**) |
| $H_G$ | 全球活跃 Homebrew 装机 |
| $W$ | 全球 webOS 设备总数 |
| $r$ | 其中"可越狱的 LG 电视"占比 |
| $\rho_G,\rho_{CN}$ | 全球 / 中国的越狱渗透率 |
| $\kappa$ | $\rho_{CN}/\rho_G$,中国越狱倾向倍数 |
| $S_t,\sigma_t$ | 第 t 年 LG 中国出货量 / 存活率 |
| $B_{CN}$ | LG 中国在用保有量 |
| $I$ | 我们的活跃装机 |
| $c$ | 我们的用户中身处中国大陆的比例 |
| $p$ | 中国 Homebrew 用户中装了 BiliTV 的比例 |

### 3.1 估计量

**装机计数恒等式**(两条路径共同的地基):

$$I \approx D_v \quad\text{(某一版本的 ipk 下载数)}$$

依据:Homebrew 自动更新对每台设备、每个版本各拉一次 ipk。误差项:①手动从 GitHub 下载
(高估,开发者/镜像站)②跳版不升级的设备(低估)③重装(高估)。方向相反,量级未知,
但**同一口径下比较时误差大部分抵消** —— 这正是 §四 只追踪比值的原因。

**路径 A(市场漏斗)**

$$\rho_G=\frac{H_G}{W\cdot r},\qquad B_{CN}=\sum_t S_t\sigma_t,\qquad N_{CN}=B_{CN}\cdot\rho_G\cdot\kappa$$

**路径 B(自身反推)**

$$N_{CN}=\frac{I\cdot c}{p}$$

**路径 C(按比例分配)**

$$N_{CN}=H_G\cdot s\cdot\beta,\qquad s\sim\mathrm{Beta}(x+\tfrac12,\;n-x+\tfrac12),\qquad \beta=\beta_{fill}\cdot\beta_{voice}$$

$x=2,n=206$ 为实测计数。用 Jeffreys 先验的 Beta 后验(而不是点估计 $\hat s=x/n$)是因为
**小计数下点估计毫无意义**:2/206 的 95% Wilson 区间是 0.27%–3.5%,跨了一个数量级,
这份不确定性必须原样传到 $N_{CN}$ 上,不能在中途蒸发。

### 3.2 六处近似,逐个检验

**1. 存量-流量近似 $B_{CN}\approx \bar S\cdot L$ —— 有偏,方向已知。**
严格式是 $\sum_t S_t\sigma_t$(带存活函数的卷积)。用"年均出货 × 寿命"等价于假设
**出货持平 + 阶跃存活函数**。而 LG 在中国份额是**逐年下滑**的(外资合计已不足 3%),
所以该近似**高估** $B_{CN}$。已用折减因子 $\delta\in[0.6,1]$ 吸收。

**2. 分母口径不匹配 —— 原文档确实错了。**
2.4 亿是"webOS 设备",**包含第三方品牌电视、商显、车机**,而 Homebrew 只跑在
特定固件版本的 LG 电视上。用它做分母会**系统性低估** $\rho_G$,进而低估路径 A。
已引入 $r\in[0.45,0.75]$ 修正。**这是原文档"两条路径矛盾"的主因之一** —— 矛盾是我算错了,不是发现。

**3. 等比迁移 $\rho_{CN}=\kappa\rho_G$ —— 数学上成立。**
率的迁移严格应在 logit 尺度做($\text{logit}(\rho)=\log\frac{\rho}{1-\rho}$),
但 $\rho\approx 1.4\times10^{-4}\ll 1$ 时 $\text{logit}(\rho)\approx\log\rho$,
乘法迁移与 logit 迁移的差异 $<0.02\%$,可忽略。**这一步没问题。**

**4. 区间端点相乘 —— 不成立,已废弃。**
原文档把 $[10万,30万]\times 7 \times 0.014\%$ 端点直接相乘得 $[100,280]$。
这等于假设**所有输入同时取同一侧极值**,若各因子独立,该组合的概率约 $0.5^k$($k$=因子数),
得到的不是区间而是"几乎不可能发生的角点"。已改为蒙特卡洛抽样取分位数。

**5. Jensen 不等式 —— 路径 B 的均值代入是错的。**
$1/p$ 是凸函数,故 $\mathbb{E}[1/p] > 1/\mathbb{E}[p]$。把"p 的中间值"代入 $I/p$
会**系统性低估** $N_{CN}$,且 $p$ 越不确定、低估越多。蒙特卡洛对 $1/p$ 直接抽样,不受此影响。

**6. 用路径 B 算覆盖率 —— 循环论证,原结论作废。**

$$\theta=\frac{I\cdot c}{N_{CN}}=\frac{I\cdot c}{(I\cdot c)/p}=p$$

**算出来的恒等于假设进去的 $p$。** 原文档"覆盖率 50–90%"就是这么来的 —— 它只是
"我假设 p 在 0.3–0.9"的复述,零信息量。覆盖率**必须用与我们自身数据无关的分母**,
即路径 A:$\theta = I\cdot c/N_A$,结果是**中位 20%,80% 区间 8%–51%**。

**7. 华人离散人口 —— 原文档漏了。**
$I$ 里包含海外华人用户(我们在 Reddit/V2EX 都有曝光,LG 电视在北美欧洲更普及),
所以"我们的装机 ⊆ 中国区设备"**不成立**,$N_{CN}\ge I$ 这个下界无效。已引入
$c\in[0.55,0.9]$。严格说我们服务的人群是"**中文用户**"而非"中国大陆用户",
若把目标改成前者,分母还要加上海外华人持有的 LG 电视。

**8. 路径 C 的"等比分配" $N_{CN}=H_G\cdot s$ —— 成立,但 $s$ 的定义域必须对齐。**
按比例分配本身没有近似误差(它就是定义:$N_{CN}=H_G\cdot\frac{N_{CN}}{H_G}$),
风险全在**用参与者份额代替用户份额**:$s_{\text{参与者}}\neq s_{\text{用户}}$。
两者之比就是 $\beta$,而 $\beta$ 有一半($\beta_{fill}$)是实测的,另一半($\beta_{voice}$)是先验。
**方向已被数据钉死**:未修偏的 317 台低于我们自己数出来的 238–390 台,所以 $\beta>1$ 确定无疑
—— 这是全文里唯一一处"偏差方向由数据而非直觉判定"的修正。

**9. 三条路径的独立性 —— 部分成立。**
A 与 B 完全独立(一个是行业数据,一个是我们的下载量)。C 与 A 共用 $H_G$
(A 用它算 $\rho_G$,C 用它当分母),所以**不完全独立**,几何平均会略微低估融合区间的宽度。
C 与 B 独立。

### 3.3 蒙特卡洛结果(300,000 次抽样)

| 估计 | 中位 | 80% 区间 |
|---|---|---|
| 路径 A(市场漏斗) | 1,531 | 624 – 3,758 |
| 路径 B(自身反推) | 503 | 347 – 790 |
| 路径 C(按比例分配) | 1,271 | 434 – 3,110 |
| **融合(对数尺度几何平均)** | **992** | **615 – 1,551** |
| **覆盖率(分母用 A×C,均与我们无关)** | **23%** | **12% – 46%** |

融合用几何平均是因为三条路径都是**乘性模型**,误差在对数尺度上近似对称;
算术平均会被路径 A、C 的长尾拉偏。

三条路径的中位数落在 503 / 1,271 / 1,531,**最大分歧只有 3 倍** —— 对一个隐藏人口估计来说
这是相当好的收敛(隐藏人口文献里跨方法差 5–10 倍很常见)。而且分歧方向是可解释的:
路径 B 偏低是因为它把"没装 BiliTV 的中国用户"压在 $p$ 里,而 $p$ 的先验上界 0.9 可能太乐观。

**自洽性检查**:99.1% 的抽样里覆盖率 ≤100%(超过 100% 意味着我们的装机比整个盘子还大,
即模型自相矛盾)。原先的区间端点算法下,这个比例是 0% —— 那才是真正的矛盾信号。

### 3.4 仍未处理的问题

- **输入间的相关性**:蒙特卡洛假设各因子独立,但 $r$(可越狱占比)与 $H_G$(活跃装机)
  实际负相关(都受"老固件更容易越狱"影响)。忽略相关性会**低估**区间宽度。
- **$\kappa\in[1.5,8]$ 是先验,不是测量**。它是全模型里最弱的一环,直接主导路径 A 的结果。
  若某天拿到 webosbrew 的国别数据,$\kappa$ 可被实测,整个路径 A 的区间会收窄一个数量级。
- **路径 C 的分子只有 2 个人**。样本量是硬约束:整个生态填了 location 的人只有 206 个。
  Beta 后验如实反映了这点(区间跨 7 倍),但再多的建模也变不出信息 —— 要收窄只能扩样本
  (把 star 用户纳入需要更高权限的 token;fork 者、commit 邮箱域名是下一批可测对象)。
- **$\beta_{voice}$ 仍是先验**。$\beta_{fill}$ 已实测,$\beta_{voice}$ 没有。
  可测的替代:同一批 issue 里,正文语言为中文的比例 —— 实测为 0,说明中文用户在英文仓库
  **连中文都不写**,只能说明 $\beta_{voice}>1$,给不出数值。

## 四、每月自动追踪(唯一保留的自动化)

只记录两个**纯硬数据**,不含任何假设:

```
全球 Homebrew 活跃装机 = hbchannel 最新版 ipk 下载数
我们的活跃装机       = 我们近 3 个版本 ipk 下载数的均值
比值                 = 我们 / 全球        （2026-08-02 基线:1.33%）
```

比值的**走势**比绝对值有意义得多:同一把尺子量涨跌是准的。
配合日活(tools/dau-daily.sh)一起看:装机是存量,日活是活跃度。

路径 C 的钥匙用 `node tools/market-geo.mjs` 复跑(追加 `tools/.market-geo.jsonl`)。
它比 §四 的硬数据慢得多(要拉 800+ 份 GitHub 资料),不进月度自动化,重估时手动跑一次即可。

## 五、被否决的方案(以及为什么)

| 方案 | 否决理由 |
|---|---|
| **论坛发问卷**(恩山/V2EX)测"装了 BiliTV 的比例" | **代表性不成立** —— 恩山用户代表不了中国 Homebrew 用户;V2EX 还被我们自己的宣传帖污染过 |
| **捕获-再捕获**(B站 教程评论者) | 违反样本独立性(同平台同算法)与捕获概率同质性;实测两视频重叠仅 1 人,估计值极不稳 |
| **多重系统估计**(跨平台名单) | 跨平台匹配用户身份不可靠,且涉及个人数据 |
| **收藏率/播放量推转化** | "收藏=潜在装机上界"是拍脑袋 —— 真正会折腾的人恰恰不收藏 |
| **网络规模法(NSUM)** | 需要向一般人群发问卷,我们没有这个渠道 |
| **B站 教程播放量 × 转化率** | 转化率无法实测(没有任何视频在讲我们的 app,做不了自然实验);且教程观众混入大量三星/索尼/小米用户 |
| **注意力份额**(B站 vs YouTube 同题教程播放量之比) | **实测后否决**:结果随查询宽严在 0.01%–19.5% 之间横跳。宽查询("LG电视 安装第三方应用")在 B 站捞到大量通用智能电视内容(281 万播放),严查询(标题必须同时命中 webOS/LG 与 越狱/装应用)在 B 站只剩 **1 个视频 196 播放**,而 YouTube 有 29 个视频 310 万播放。分母不可比 —— 中文用户查这事去恩山/知乎/百度,不去 B 站 |
| **issue 正文语言**(中文 issue 占比当份额) | **实测后否决**:5 仓库 7,921 条 issue 里中文 0 条。不是管线坏了(原始 JSON 里确有汉字),是**行为**:中国用户在国际仓库一律写英文。这把钥匙只能给出"$\beta_{voice}>1$",给不出数值 |

## 六、什么情况下该重估

- 出现**第二个中国向 webOS 应用** → 可以做真正的交叉验证(两个应用的装机重叠/比例)
- webosbrew 官方公布按国家的下载分布 → 直接拿到分母,本文档作废
- 我们的装机量出现数量级变化 → 路径 B 的锚点变了,结论要重算
- 生态里填 location 的人数翻倍(现在只有 206) → 路径 C 的区间可以显著收窄,值得重跑

## 七、一句话总结

**全球 32,658 台活跃 Homebrew 设备,中国区约 990 台(615–1,550),我们占其中约 23%。**
三条互不依赖的路径(行业漏斗 / 自身下载反推 / GitHub 地理份额)分别给出 1,531 / 503 / 1,271,
最大分歧 3 倍。这个盘子小到**不值得再花力气把区间收窄**——
增长的天花板不在"覆盖率还差多少",而在"中国还有多少台 LG 电视会被越狱"。
