# 2.2.3 c9-test.1 — C9 起播测试包

这是 #34 的诊断测试包，正式版仍为 v2.2.3。自动更新与 Homebrew 不推送此包，测试分支暂不合并。

## 这次改动

- 加载生成的 DASH 清单时明确指定 MIME，避免 Shaka 对本地 Blob 做失败的 HEAD 格式探测。普通加载、编码回退和画质切换失败后的恢复都覆盖。
- 起播报告增加阶段派发时间、首个请求/响应节点、音视频写入完成时间和缓冲状态；将清单/媒体重试按错误码区分。
- 设置与扫码报告带 `c9-test.1`，便于确认装的是测试包。自动 CDN 选路策略、重试次数与缓冲阈值保持 v2.2.3 的配置。

真实 Shaka 浏览器对照中，未指定 MIME 出现 4 次 Blob HEAD 失败；指定后归零。这不能单独解释自动模式约 17 秒、手动约 7 秒的全部差距，也不代表已经在 C9 验证提速。

## 安装与回退

从此页面 Assets 下载文件名带 `c9-test.1` 的 `.ipk`，用原先的 Developer Mode / Dev Manager 安装方式覆盖安装。应用 ID 与 webOS 包版本仍为 `com.biliwebos.app` / `2.2.3`。进入设置，确认显示 `2.2.3 c9-test.1`；安装器显示的数字版本仍为 2.2.3。

无需先卸载；卸载可能清掉登录与设置。若安装工具提示版本相同，请使用其重新安装/覆盖功能。需要回退时覆盖安装 [正式版 v2.2.3 的 IPK](https://github.com/asdf17128/bili-webos/releases/download/v2.2.3/com.biliwebos.app_2.2.3_all.ipk)。

## 请帮助做两组对照

1. 用之前慢的**同一视频、同一分 P**，固定 **1080P / AVC / AAC**；附上 BV 号、地区及网络类型即可，无需 Cookie 或带签名播放地址。
2. 先选**自动**，退出应用并重新打开，测第一次起播；接着返回列表，再打开同一视频两次。每次出画面后返回设置 → 网络诊断，扫码取得报告，直接贴回 **#34**，标注自动 1/2/3。
3. 再选之前改善明显的**腾讯（或阿里）**，同样重开应用、测三次，标注所选线路及 1/2/3。请记录主观等待秒数，与报告一起提供；不需要提交六个新 issue。
4. 如果某次一直加载或黑屏，也请保留该次诊断报告，不必反复重试到成功后才上报。

报告保留首段实际节点，后续诊断测速不会覆盖这些字段。首次与重复打开分开看；C4 回归不能替代 C9 验收。收到反馈后再决定后续修复和正式发布。
