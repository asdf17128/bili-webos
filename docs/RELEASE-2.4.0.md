# 2.4.0 发布验收

本版合并 PR #17 的受限 Dolby Vision 路径，补齐会员自动画质与身份标识，并修复退出登录、旧电视封面、媒体代理端口及长时间播放的资源清理和恢复。

## Issue 与 PR 范围

- #17：保留贡献者原始提交；特定 4K120 源以受审计的 60fps 路径播放，其他源不强套转换。集成时保留当前解码边界、取消请求与恢复逻辑。
- #33：支持影院宽 4K、Profile 5/8 检测及独立高级音轨；自动选择账号和设备支持的最高档。音轨标签不等于音响 Atmos 输出认证，C6H 的具体组合仍需原报告者复验。
- #34：修复 Chrome 53 图片观察器兼容、完整退出账号及代理端口协商。UP 主列表、搜索排序、导航调整作为后续功能，不以本版已实现回复。
- #29/#35/#37/#38/#48：增加有界恢复、保留原始签名备用地址和家庭网络检测方案。海外线路、CDN 403 与账号风控保留现场待确认状态。
- #30：订阅功能已在此前版本提供，本版回归关注入口和动态列表。
- #39：授权范围讨论不属于代码缺陷，本版不更改授权结论。

## 实体屏幕验收边界

2026-10-14 用户指出现场未看到电视打开。此前通过 192.168.50.94 的 SSH 隧道连接电视 CDP，完成设备运行时 UI 冒烟（53 项通过，3 项警告），并读取页面截图；这证明电视上的 WebApp 运行状态，不能证明实体面板已经点亮或画面输出正确。

已停止后续真机自动测试队列。重新查询 CDP 得到 `visibility=visible`、`hasFocus=true`，但公共 Luna 的电源与前台查询均返回 `Denied method call`，无法独立确认面板状态。正式包会员专项、循环及长播队列尚未执行，不得视为通过。随后用户要求完成 Nerd 信息开关并继续测试、发布。后续设备测试只报告运行时数据，不将其作为实体面板亮屏、HDR 标识或外接音响输出的证明；结果另列于下方。

用户随后明确确认「能看到 BiliTV 画面」。用户进一步说明是自己手动打开电视，不能视为自动唤醒成功。这补充了实体亮屏与前台应用的人工确认；CDP 的解码和资源数据仍不等同于面板 HDR 标识、色彩正确性或音响 Atmos 输出认证。

### 一次未复现的画质切换超时

第一次杜比专项在暂停的 4K→Profile 5 切换中未在测试的 25 秒窗口内满足预期状态，自动队列因此停止。该失败原样保留。原测试 finally 在清理前未抓取状态，因此无法确定当时是网络延迟、恢复原画质还是解码未就绪，也不能仅凭服务端相邻的 aborted 记录归因。

补充失败快照后，同包完整专项通过；另外连续 6 轮 4K↔Profile 5、暂停保持与未缓冲跳转的 30 项检查通过，16 条媒体请求中止均标记为主动取消。没有以此宣称找到并修复首次超时的根因；它作为间歇性问题继续关联 #33。确定性浏览器用例另验证了画质请求/加载失败时保留原流与偏好的行为。

原始失败、复测与设备计数见 [本轮证据](ux-evidence/2026-10-14-release-240/)。

## 长播延期与收尾修复

用户明确要求长时间测试留到下次。25 分钟 4K50 长播在约 8 分钟、9 次采样后主动停止；原始工具将 SIGTERM 记为 FAIL，保留此结果，不改写为完整通过。15 分钟直播耐久未开始。两项均不作为本版已完成验收，后续需独立重新计时。已退出测试播放并恢复偏好。

收尾发现未登录时设置页缺少退出登录行，滚轮从语言选项无法跨过空行抵达 Nerd 开关。修复为按登录状态分配连续焦点行，并避免与隐藏退出项重复注册。新增用例修复前失败，修复后 Nerd 专项 3/3 通过。
