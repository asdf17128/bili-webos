# 稳定性发现的修复与复核（2026-10-13）

本轮针对 [候选 4 稳定性报告](STABILITY-RESULTS-2026-10-13.md) 的三个发现继续处理。源码标记为 `2.3.0 stability-test.5`，未发布、未推送、未更新 Homebrew；电视仍是候选 4。本报告的本地结果不能替代新包真机验收。

## 直播恢复

- 每次重连重新请求直播 API，仅从该响应同格式、同编码的 `url_info` 选择完整签名地址，保持画质，不套用点播镜像规则。
- 对网络错误、断流和起播超时记录失败 host，60 秒内优先选其他节点；所有节点均失败时轮换到最早失败的节点，防止反复黏在主节点。解码错误不直接判定 CDN 失效。记录最多 6 个 host。
- 已播放直播的空缓冲卡顿，6 秒未推进开始准备恢复，监测间隔 1 秒；仍有超过 1.5 秒缓冲则保留 12 秒容错。暂停、跳转、取源中、等待重试和终止状态均不会反复触发 watchdog。
- 受控浏览器验证的是 **8 秒内重新取源/赋源**，不等于电视 8 秒内恢复画面。先前真机 13.326 秒间隔的实际改善仍待测。

旧版 CDN 与 8 秒边界用例均失败，新版通过；额外捕获并修复“全部节点失败”和“非法 host 成为兜底”两项边界。最终选择器 10 项、真实 React/受控媒体事件 14 项覆盖签名保持、画质保持、短卡顿、暂停、有缓冲容错及失败记录过期。

## 检查更新

电视优先读取 `version.json`；网络错误、非 200、解码/JSON/版本格式异常时，再尝试 GitHub Release API 一次。每路客户端期限 7 秒，两路都失败明确返回失败，避免将异常内容当成版本号。诊断仅存来源类别、HTTP 状态与固定错误分类。

期限到达会取消客户端 SDK 请求句柄；这不证明服务中已发出的 HTTP 在该时刻被物理中止。其他 API 原有期限不变。原先两次更新失败缺少 HTTP/错误分类，不能反推其现场根因。

生产 client 模块的受控 Luna 边界覆盖正常 JSON、Base64、网关 HTML、坏 JSON、null、非法版本、连接重置、双源失败、单源/双源悬挂；10 项通过。旧版已有 9 项中的 7 项失败；后来新增双悬挂边界。测试已注册到 `tools/verify.sh`。
